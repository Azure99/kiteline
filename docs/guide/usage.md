# 使用工作台

[English](usage.en.md)

本文面向已经接入设备的拥有者，说明如何在浏览器中使用工作台。接入设备见[接入设备](devices.md)，定时任务见[定时任务](scheduled-tasks.md)。

## 浏览器与界面

### 支持的浏览器

工作台支持桌面 Chrome 和 Android Chrome，最低 Chromium 97（实现见[浏览器兼容](../design/architecture.md#浏览器兼容)）。通过 HTTPS 或 `localhost` 访问时，当前版本的 Chrome 可以从菜单把工作台安装为应用，以独立窗口打开；它仍需连接 server，没有离线功能。

### 登录与语言

主机名或协议不同的入口（例如 `http://192.168.1.10:8080` 和 `https://kiteline.example.com`）分别登录；同一主机、同一协议的不同端口共用登录。语言等偏好按入口（含端口）分别保存在浏览器中。退出登录前会确认放弃未保存的文件；退出只结束这个浏览器的登录，终端会话继续运行。忘记密码时见[重置初始化 token 与密码](server.md#重置初始化-token-与密码)。

语言默认跟随浏览器：中文环境显示简体中文，其他显示英文。切换语言不影响打开的文件和终端。

地址栏记录设备、工作区、工具以及打开的文件、仓库和会话，可以前进、后退和收藏。顶栏的状态点表示浏览器与 server 的连接，不代表设备是否在线。

server 升级后，已打开的页面显示 Web 和 Server 的版本并暂停远程操作；先复制未保存的内容，再点“刷新页面”。

布局随可用窗口宽度变化，规则见[布局](../design/interaction.md#布局)。

### 设置保存在哪里

| 内容                                   | 保存位置                   |
| -------------------------------------- | -------------------------- |
| 语言、最近工作区、终端字号             | 当前浏览器                 |
| 终端分组和分屏、未保存的修改、提交消息 | 当前页面，刷新或关闭后丢失 |
| 新会话滚屏行数、终端快捷方式           | 设备，所有入口共用         |
| 设备名称                               | server                     |
| 工作区名称和路径                       | 设备                       |

## 设备与工作区

### 设备

绑定新设备见[用网页命令接入](devices.md#用网页命令接入)，版本不匹配时见[升级 agent](devices.md#升级-agent)。

删除设备后，server 删除设备记录、绑定和定时任务摘要，远程访问立即断开。设备上的 agent、终端会话、定时任务和文件都保留，但 agent 无法再连接，重新接入需要再次绑定。删除记录不会[卸载 agent](devices.md#卸载)。

### 工作区

工作区是设备上登记的一个项目目录。在在线设备的“添加工作区”中选择项目目录；路径按解析符号链接后的真实目录登记，重复添加同一目录得到已有的工作区。

移除工作区只删除登记，目录和文件保留；设备离线或工作区里还有终端会话时无法移除。

工作区不是沙箱：终端、文件和 Git 以项目用户的权限工作，能访问该用户能访问的任何路径。

切换工具、工作区或设备时，终端会话继续运行。离开工作区会关闭它的终端画面，回来后重新附着；分组和分屏布局、未保存的修改和 Git 提交消息保留到页面关闭。

## 终端

终端会话运行在设备上：关闭页面、断网、退出登录、server 重启或删除设备都不会结束它。会话在 Shell 或快捷命令退出、你结束它、agent 停止或设备重启时结束，完整列表见[会话生命周期](../design/terminal.md#会话生命周期)。同一会话可以同时在多个浏览器和本机打开，各客户端都能直接输入，同时输入的字符会交错。

### 新建会话与快捷方式

新会话在工作区目录启动，继承 agent 的环境变量（agent 作为服务运行时来自服务配置，见[后台运行](devices.md#后台运行)）。Linux 和 macOS 使用项目用户的登录 Shell，Windows 使用 PowerShell 7，可在 [agent 配置文件](reference.md#agent-配置文件)中更换。

快捷方式在登录 Shell 中运行一条命令，命令退出时会话结束。新设备预置的 AI CLI 程序需要自行安装。

“关闭显示”只关闭画面，会话继续运行，可从“选择终端会话”重新打开。

### 复制与粘贴

向上滚动即可看到保留的历史，新输出不会把你拉回底部，“回到底部”回到最新输出。各客户端的滚动和选择互不影响。

- 桌面：拖选文字，程序接管鼠标时（例如 htop）按住 Shift 拖选；用右键菜单复制，macOS 也可用 Cmd-C。粘贴用 Ctrl-Shift-V、Cmd-V 或右键菜单。Ctrl-C、Ctrl-V 发给程序。
- 手机：长按选词并拖动两端手柄，点“复制所选文本”。轻点终端或点“键盘”打开输入法；浏览器允许读取剪贴板时有“粘贴”按钮。

粘贴过大时不发送，提示“粘贴内容超过容量”。程序显示图片或通过 OSC 52 写剪贴板在网页中不起作用。

手机快捷键中的 SHIFT、CTRL、ALT 点一次对下一个按键生效，再点取消。网页中的 Ctrl-b 直接发给程序，不是 tmux 前缀。

### 搜索与显示

终端搜索在当前画面已加载的内容（含历史）中查找，不区分大小写。

“终端设置”中的“新会话滚屏行数”决定会话保留多少行历史（范围见[限额](reference.md#限额)），只对之后新建的会话生效。

一个会话只有一组行列，由最近输入或调整窗口的客户端决定，其他客户端随之重排；手机打开输入法不改变尺寸。

### 连接与恢复

打开会话后，恢复画面和历史才能输入。连接失败时可重连；容量不足时可减少历史重试，只恢复当前画面，设备上的历史不变。历史缺口表示记录器故障期间的部分输出缺失。会话结束后画面只读，并显示退出码。

“恢复终端”重建记录后重新附着到同一个程序，不重启程序。连接正常但画面错乱时，用会话菜单的“重绘程序”：它临时改变一次尺寸让程序重绘，其他客户端的画面和选区也可能变化，所以要先确认。仍不正常时“关闭显示”后重新打开。机制见[恢复动作](../design/terminal.md#恢复动作)。

会话菜单的“结束会话”确认一次后，结束会话及其中的全部程序。

### 本机接续

网页会话菜单的“本机接续命令”给出附着到该会话的命令，在设备上以项目用户、在真实终端中执行，不需要 sudo。例如：

```sh
/usr/local/bin/kiteline-agent attach SESSION_ID --run-dir '/home/PROJECT_USER/.local/share/kiteline-agent/run'
```

附着后，Ctrl-b d 断开附着（会话继续），Ctrl-b Ctrl-b 发送 Ctrl-b，Ctrl-b [ 用 tmux 复制模式查看历史。agent 运行时也可以在本机管理会话：

```sh
kiteline-agent workspace list
kiteline-agent terminal new --workspace WORKSPACE_ID
kiteline-agent terminal list --workspace WORKSPACE_ID
kiteline-agent attach SESSION_ID
kiteline-agent terminal end SESSION_ID
```

`workspace list` 给出工作区 ID，`terminal new` 创建会话后立即附着。各命令的输出和选项见 [kiteline-agent 命令](reference.md#kiteline-agent-命令)。

Windows 上在 PowerShell 7 控制台中执行本节交互命令时，把 `kiteline-agent` 换成 `& "$env:ProgramData\kiteline-agent\kiteline-agent.ps1"`；调用方式的选择见 [kiteline-agent 命令](reference.md#kiteline-agent-命令)。本机命令和 agent 必须解析到同一个运行目录（见 [agent 环境变量](reference.md#agent-环境变量)）；只在服务配置中设置了 `KITELINE_AGENT_RUN_DIR` 时，本机命令也要设置同样的变量，`attach` 也可以用 `--run-dir`（网页复制的命令已包含）。容器见[在容器中运行](devices.md#在容器中运行)。

## 文件

文件工具浏览和编辑当前工作区的文件，路径相对于工作区目录显示。

### 浏览

文件名不是合法 UTF-8 的项，以及 FIFO、socket 和设备节点，请在终端处理。

文件被其他程序改动后列表自动刷新，页面可见时也定时刷新。设备无法监听目录时仍可定时刷新。

### 打开与编辑

PNG、JPEG、GIF、WebP 图片按内容识别并预览，超过预览大小或像素数时只能下载。其他文件按 UTF-8 文本打开；包含 NUL 字节、不是合法 UTF-8 或超过编辑容量（见[限额](reference.md#限额)）的文件只能下载，不能编辑。

编辑器保留原有的 BOM、换行符和末尾换行；混用换行时会提示保存采用 LF 还是 CRLF。一次修改会让内容超过编辑容量时整体不生效。复制内容不表示已保存。

保存通过新文件替换原文件，父目录必须允许创建文件和重命名。普通权限位会保留；属主、属组、ACL 和扩展属性按新建文件的规则确定，其他硬链接仍指向旧内容。保存符号链接时写入它指向的文件。

### 草稿

未保存的修改（草稿）只存在于当前页面：

- 切换文件、工具、工作区或设备时保留。“打开的文件”可找回所有设备上打开的草稿。
- 刷新或关闭页面时浏览器会提示，确认离开后草稿丢失。
- 设备离线、设备或工作区被删除时，内容仍可查看和复制，但不能保存到原位置。

### 保存冲突

文件自打开或上次保存后被改过时，保存不执行，也不会自动重载。用“核对磁盘内容”查看当前磁盘文本，再决定加载磁盘版（放弃草稿）、覆盖这一版本或暂不处理。

保存结果不确定（例如保存中断线）时，先核对磁盘内容与上次发送内容是否一致，再决定下一步。

### 搜索

文件搜索支持正文和文件名，规则如下：

- 按字面文本匹配，区分大小写。
- “文件名”在文件的相对路径（含目录部分）中查找包含查询文本的文件，结果只有文件。
- 包含隐藏文件，不搜索 `.git`，不进入任何符号链接（指向文件或目录的都不进入）。
- `.gitignore` 只在 Git 仓库内生效，`.ignore` 和 `.rgignore` 始终生效；勾选“包含已忽略项”可搜索被这些规则排除的文件。
- 结果数量和时间有上限（见[限额](reference.md#限额)），达到时显示“结果不完整”；路径不是合法 UTF-8 的结果不显示，也标为不完整。

### 新建与重命名

名称已存在时，新建和重命名都失败，不覆盖。重命名或移动后，打开的标签跟随到新路径。工作区根目录和正在保存的文件不能重命名、移动或删除。

### 上传与下载

上传逐个发送所选文件，目录不能上传。数据发完后仍需等待设备完成；收起对话框不会取消上传。下载交给浏览器的下载管理器，目录不能下载。大小上限见[限额](reference.md#限额)。

### 整理文件

- 复制目录会递归复制，符号链接复制为链接本身，硬链接复制为独立文件。
- 同一文件系统内移动是改名，跨文件系统移动先复制再删除源。
- 目标已存在时该项失败，不覆盖文件，不合并目录，见[同名处理](#同名处理)。

删除是永久删除，没有回收站。目录递归删除，包括挂载在其中的其他文件系统里的数据，挂载点可能保留。删除符号链接只删链接本身。FIFO、socket 和设备节点不能复制、移动或删除，包含它们的目录只能部分删除。

### 同名处理

上传、复制或移动的目标已存在时，点该项的“同名处理”：

- “保留两份”：使用另一个路径；执行时该路径已被占用，该项仍会失败。
- “替换”：覆盖这个文件，目录不能替换；确认后目标又被改动时，替换不执行。目标是符号链接时只替换链接，原目标文件不变。

### 操作结果与取消

每项结果为“已完成”“未完成”（未执行或确认失败，磁盘没有变化）、“部分完成”（例如目录中的部分文件已处理）或“结果未确认”（执行中失去联系，先查看磁盘再决定）。取消只停止尚未开始的部分，已完成的部分保留。未完成的项可以修改后“重试未完成项”。

### 符号链接

文件工具跟随项目用户能访问的符号链接，可以经链接浏览工作区外的目录。打开和保存作用于链接指向的文件，重命名、移动、删除和替换只作用于链接本身。

目录上传、打包下载和跨工作区复制等不在文件工具中提供，见[范围外](../design/files.md#范围外)。

## Git

Git 工具使用设备上的 Git 和项目用户的 Git 配置，hooks、签名和凭据按设备配置生效。安装前提见[支持的系统与准备](devices.md#支持的系统与准备)。

### 仓库发现与切换

Git 工具扫描工作区目录及其所有子目录，列出找到的仓库，包括已初始化的子模块和位于工作区内的 linked worktree（标为 `worktree`）。工作区之外的仓库不会被使用：工作区如果只是某个仓库的子目录，会显示“没有发现 Git 仓库”，请把仓库根目录添加为工作区。

有多个仓库时自动选中第一个，用仓库菜单按路径切换。“重新发现仓库”重新扫描；显示“仓库扫描未完成”时点“继续扫描”。裸仓库不支持。

### 状态与 diff

diff 超过限额时只显示部分原始 patch。变化列表分页，但组标题的数量是整个仓库的。路径不是合法 UTF-8 的项不能操作。

### 暂存与提交

- 暂存的是磁盘上的文件，不包括未保存的草稿。
- 操作会连带改变未选中的路径时不执行，并列出这些路径和需要先做的操作。
- 取消已暂存的重命名时同时处理新旧两个路径；“只取消暂存新路径”只处理新路径。

提交包含暂存区的全部内容，不限于当前页或勾选的行。消息为空、有未解决的冲突或没有暂存的更改时不能提交。

### 丢弃更改

“丢弃未暂存更改”恢复为暂存区中的版本，“丢弃全部更改”恢复为 HEAD 中的版本。执行前核对每项将被恢复还是删除；列为删除的文件（例如未跟踪文件）被永久删除。核对后文件又变化时不执行，需要重新核对。

### 分支与历史

“分支”视图列出本地分支，被其他工作树检出的分支显示其路径，不能切换或删除。切换不强制覆盖本地修改；删除执行 `git branch -d`，未合并的分支会被拒绝；Git 拒绝时显示[结果未确认](#结果未确认)。

历史中的 diff 与父提交比较，合并提交可以选择父提交。

### 同步与认证

Pull 执行 `git pull`，合并时使用默认提交消息，配置为交互式 rebase 的 pull 会失败。Push 执行 `git push`，没有强制推送。

认证无法交互，Git 不会弹出用户名或密码输入：SSH 密钥、ssh-agent 或凭据助手必须在 agent 的环境中无需输入即可使用。认证失败时，点反馈中的“终端”，在同一工作区的终端里运行相同的 Git 命令完成配置（例如让凭据助手保存凭据），再回来重试。agent 作为服务运行时见[后台运行](devices.md#后台运行)。

### 冲突与继续

仓库处于 merge、rebase、cherry-pick、revert 或 am 中时（包括在终端中开始的），顶部显示操作名称和原因，并提供“继续”“中止”和“在终端处理”：

1. 在文件工具或终端中解决冲突并保存。
2. 在 Git 中点冲突行的加号，标记已解决。
3. 没有冲突后点“继续”，使用默认的提交消息。

“中止”确认后让 Git 恢复操作前的状态，未提交的内容可能受影响。网页只能继续由普通 pick 步骤组成的 rebase；含 edit、reword、squash、fixup、exec 等步骤的 rebase 和无法识别的操作，请在终端中完成后回到网页刷新。

### 结果未确认

同一仓库一次执行一个 Git 写操作，其余排队，执行中可以“取消操作”。以下情况下工作台无法确定仓库的状态，显示“结果未确认。请刷新核查后再决定是否重试。”：

- Git 命令以失败状态退出，例如 push 被拒绝、hook 拒绝提交、存在 `index.lock`；
- 执行中失去联系；
- 操作被取消；
- 超过写操作时限（见[限额](reference.md#限额)）。

处理：展开“Git 输出”查看 Git 的原始输出，点“刷新 Git”确认分支、提交和变化，确认没有生效后再手动重试。工作台不会自动重试。

多步操作只完成一部分时显示“操作部分完成。”Stash、按行暂存等需要在终端中完成，见[范围外](../design/git.md#范围外)。

## 访问开发服务

工作台可以打开设备上监听本机端口的 HTTP 服务，包括 WebSocket（含热更新）和 SSE。链接需要工作台登录，不是公开分享。关闭页面不会停止开发服务；退出登录、登录到期或删除设备会断开已打开的连接。

### 打开端口

在设备的“访问端口”中输入端口。候选是一次快照，可能包含非 HTTP 服务；未列出的端口也可以手工输入。

服务必须在 agent 所在的机器（或容器）中监听 `127.0.0.1`、`::1`、`0.0.0.0` 或 `::`。容器见[在容器中运行](devices.md#在容器中运行)，候选规则见[端口建议](../design/http-access.md#端口建议)。

终端输出中主机为 `localhost`、`127.0.0.1`、`[::1]`、`0.0.0.0` 或 `[::]` 的 `http:` 链接会转换为该设备端口的地址：桌面上点击打开，手机上长按选中完整链接后点“访问设备端口”。其他链接按原地址打开。

### 两种路径模式

| 模式       | 地址                         | 开发服务收到的路径 |
| ---------- | ---------------------------- | ------------------ |
| “普通路径” | `/proxy/DEVICE_ID/PORT/…`    | 去掉前缀           |
| “保留路径” | `/absproxy/DEVICE_ID/PORT/…` | 包含完整前缀       |

“普通路径”适合只使用相对地址的页面。页面用 `/` 开头的路径引用资源时，请求会落到工作台根路径，表现为空白页或 MIME 类型错误；这类项目改用“保留路径”，并把项目的 base 设为 `/absproxy/DEVICE_ID/PORT/`。

开发服务收到的 `Host` 是你访问工作台的地址（如 `kiteline.example.com:8443`），工作台的登录 Cookie 不会转给它。完整规则见[地址与路径模式](../design/http-access.md#地址与路径模式)。设备 ID 可以从设备页地址 `/devices/DEVICE_ID` 取得，或选“保留路径”后“复制链接”。

### 配置 Vite

Vite 项目使用“保留路径”，在 `vite.config.js` 中设置：

```js
export default {
  base: "/absproxy/DEVICE_ID/3000/",
  server: {
    port: 3000,
    strictPort: true,
    allowedHosts: ["kiteline.example.com"],
    proxy: {
      "/absproxy/DEVICE_ID/3000/api": {
        target: "http://127.0.0.1:8000",
        rewrite: (path) => path.replace("/absproxy/DEVICE_ID/3000", ""),
      },
    },
  },
};
```

- `DEVICE_ID` 换成设备 ID，`3000` 换成开发服务端口。
- `allowedHosts` 列出访问工作台用的每个域名，不带端口；用 IP 或 `localhost` 访问时不需要。缺少时 Vite 返回 403 和 `Blocked request`。
- `server.proxy` 的键必须带 base 前缀，否则请求得到的是 `index.html`。上例中后端收到去掉前缀的 `/api/…`。
- Vite 处理的 HTML 资源自动加上 base，热更新默认经同一地址连接，不需要另外配置。

应用代码自己拼接的地址从 base 构造，路由器的 base 也用同一前缀：

```js
const base = new URL(import.meta.env.BASE_URL, location.origin);
fetch(new URL("api/status", base));
const socketUrl = new URL("socket", base);
socketUrl.protocol = location.protocol === "https:" ? "wss:" : "ws:";
const socket = new WebSocket(socketUrl);
```

### 常见错误

- 跳转到登录页：这个浏览器未登录或登录已到期，登录后自动回到原地址。
- 502：端口上没有服务、服务只监听其他地址或不是 HTTP 服务。
- 503：设备离线。426：agent 与 server 版本不一致，见[升级 agent](devices.md#升级-agent)。404：设备 ID 不存在。
- 504、429：连接超时或设备连接数已满，稍后重试。
- 空白页、MIME 类型错误：改用“保留路径”并配置 base。

这些错误页由工作台生成，是英文的；开发服务自己返回的错误原样显示。完整状态码见[错误响应](../design/http-access.md#错误响应)。

### 安全提示

开发页面与工作台同源（协议、域名、端口相同）。页面中的脚本可以像你一样调用工作台接口，包括在任何设备上执行命令、改写文件；所有项目和端口的页面共用 `Path=/` 的 Cookie、localStorage 和 Service Worker，可能互相覆盖，页面返回的 `Clear-Site-Data` 能清掉工作台登录。只打开你信任的项目，不要经这里访问来源不明的服务。机制见[安全边界](../design/http-access.md#安全边界)。
