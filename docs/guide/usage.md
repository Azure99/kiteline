# 使用工作台

[English](usage.en.md)

本文面向已经接入设备的拥有者，说明如何在浏览器中使用工作台。接入设备见[接入设备](devices.md)，定时任务见[定时任务](scheduled-tasks.md)。

## 浏览器与界面

### 支持的浏览器

工作台支持桌面 Chrome 和 Android Chrome，最低 Chromium 97（实现见[浏览器兼容](../design/architecture.md#浏览器兼容)）。通过 HTTPS 或 `localhost` 访问时，当前版本的 Chrome 可以从菜单把工作台安装为应用，以独立窗口打开；它仍需连接 server，没有离线功能。

### 登录与语言

主机名或协议不同的入口（例如 `http://192.168.1.10:8080` 和 `https://kiteline.example.com`）分别登录；同一主机、同一协议的不同端口共用登录。语言等偏好按入口（含端口）分别保存在浏览器中。“退出登录”在顶栏的更多菜单中，有未保存的文件时先询问“放弃未保存修改并退出登录？”；退出只结束这个浏览器的登录，终端会话继续运行。忘记密码时点登录页的“登录恢复”，步骤见[重置初始化 token 与密码](server.md#重置初始化-token-与密码)。

语言默认跟随浏览器：中文环境显示简体中文，其他显示英文。在更多菜单（登录页为语言图标）中可选“跟随浏览器”、English 或简体中文，切换不影响打开的文件和终端。

### 顶栏和三个工具

- Kiteline 标志：回到主页。主页顶部有“定时任务”和“绑定设备”按钮，下面依次是“最近工作区”（有记录时）和设备列表。
- 当前目标：显示当前工作区和设备，点击后打开“设备与工作区”列表切换，列表显示完整路径。
- 状态点：浏览器与 server 的连接状态（“已连接”或“连接中断”），不代表设备是否在线。
- “定时任务”图标，以及选定设备后出现的“访问端口”图标。桌面上有上传进行时还有上传状态图标，从中可以重新打开上传对话框。
- 更多菜单：“打开的文件”、语言和“退出登录”。

进入工作区后，下方是三个工具“终端”“文件”“Git”。切换工具不会结束终端会话或丢失未保存的修改。地址栏记录设备、工作区、工具以及打开的文件、仓库和会话，可以前进、后退和收藏。

server 升级后，已打开的页面显示 Web 和 Server 的版本并暂停远程操作；先复制未保存的内容，再点“刷新页面”。

### 桌面与手机布局

窗口宽度小于 960 CSS 像素时使用手机布局，与设备类型无关。手机布局没有设备侧栏，用顶栏的当前目标切换；终端一次显示一个会话并带快捷键行；文件和 Git 的列表与内容逐层进入；对话框从底部弹出；上传状态在更多菜单中。规则见[布局](../design/interaction.md#布局)。

### 设置保存在哪里

| 内容                                   | 保存位置                   |
| -------------------------------------- | -------------------------- |
| 语言、最近工作区、终端字号             | 当前浏览器                 |
| 终端分组和分屏、未保存的修改、提交消息 | 当前页面，刷新或关闭后丢失 |
| 新会话滚屏行数、终端快捷方式           | 设备，所有入口共用         |
| 设备名称                               | server                     |
| 工作区名称和路径                       | 设备                       |

## 设备与工作区

### 设备

设备状态为“在线”“离线”或“版本不匹配”，绑定新设备见[用网页命令接入](devices.md#用网页命令接入)。设备页显示最近连接时间和 agent、server 的版本，右上角菜单有“升级 agent”“终端设置”“重命名”和“删除设备”。

agent 的版本必须与 server 一致，否则设备无法连接，显示“版本不匹配”，设备页和工作区页顶部有“查看升级命令”。在升级对话框中选择设备的系统（默认是 Linux），复制命令到设备上执行，步骤见[升级 agent](devices.md#升级-agent)。设备上已有的终端会话不受影响。

“删除设备”确认一次后，server 删除设备记录、绑定和定时任务摘要，远程访问立即断开。设备上的 agent、终端会话、定时任务和文件都保留，但 agent 无法再连接，重新接入需要再次绑定。删除后对话框显示卸载命令，见[卸载](devices.md#卸载)。

### 工作区

工作区是设备上登记的一个项目目录。在线设备的设备页点“添加”，在“添加工作区”对话框中浏览设备的文件系统：输入绝对路径后点“转到目录”，或从“根目录与主目录”选择起点，需要时“新建目录”，最后点“选择此目录”。名称默认取目录名，路径按解析符号链接后的真实目录登记，重复添加同一目录得到已有的工作区。

工作区行的菜单有“重命名”和“移除”，设备离线时不可用。“移除”只删除登记，目录和文件保留；工作区里还有终端会话时无法移除。

工作区不是沙箱：终端、文件和 Git 以项目用户的权限工作，能访问该用户能访问的任何路径。

### 最近工作区与已有会话

主页的“最近工作区”是这个浏览器最近使用的工作区，点击回到上次使用的工具；确认工作区已移除后记录自动消失。设备页的“已有会话”列出这台设备上运行中的全部终端，可以“筛选会话”，点击即打开。

切换工具、工作区或设备时，终端会话继续运行。离开工作区会关闭它的终端画面，回来后重新附着；分组和分屏布局、未保存的修改和 Git 提交消息保留到页面关闭。

## 终端

终端会话运行在设备上：关闭页面、断网、退出登录、server 重启或删除设备都不会结束它。会话在 Shell 或快捷命令退出、你结束它、agent 停止或设备重启时结束，完整列表见[会话生命周期](../design/terminal.md#会话生命周期)。同一会话可以同时在多个浏览器和本机打开，各客户端都能直接输入，同时输入的字符会交错。

### 新建会话与快捷方式

点“新建终端”（加号），选择 Shell 或一个快捷方式。会话在工作区目录启动，继承 agent 的环境变量（agent 作为服务运行时来自服务配置，见[后台运行](devices.md#后台运行)）。Linux 和 macOS 使用项目用户的登录 Shell，Windows 使用 PowerShell 7，可在 [agent 配置文件](reference.md#agent-配置文件)中更换。

快捷方式在登录 Shell 中运行一条命令，命令退出时会话结束。在设备菜单或终端菜单的“终端设置”中管理，每台设备一份。新设备预置 Claude Code、Codex 和 OpenCode（命令为 `claude`、`codex`、`opencode`），程序需要自行安装。

“选择终端会话”列出本工作区的全部会话，包括其他浏览器或本机创建的，可点“刷新会话”。

### 分组与分屏

桌面上每个新会话自成一组，多组时显示组标签。“新建并分屏”下的“向右分屏”“向下分屏”在当前会话旁新建 Shell，可以继续拆分。拖动会话标题或组标签可以调整顺序、移到其他组或拆出新组，会话菜单有同样的操作。“放大当前屏”只显示一个分屏，“还原分屏”恢复。“关闭显示”只关闭画面，会话继续运行，可从“选择终端会话”重新打开。

使用文件或 Git 时，桌面上点工具行右侧的“展开终端面板”在下方显示终端，“在终端展开”切到终端工具。

“专注终端”隐藏顶栏、侧栏和工具行。桌面上同时进入全屏，退出全屏即退出专注；手机上同一按钮依次是“专注终端”“进入全屏”“退出专注”。切换设备、工作区或工具时自动退出。

### 复制与粘贴

向上滚动即可看到保留的历史，新输出不会把你拉回底部，“回到底部”回到最新输出。各客户端的滚动和选择互不影响。

- 桌面：拖选文字，程序接管鼠标时（例如 htop）按住 Shift 拖选；用右键菜单复制，macOS 也可用 Cmd-C。粘贴用 Ctrl-Shift-V、Cmd-V 或右键菜单。Ctrl-C、Ctrl-V 发给程序。
- 手机：长按选词并拖动两端手柄，点“复制所选文本”。轻点终端或点“键盘”打开输入法；浏览器允许读取剪贴板时有“粘贴”按钮。

粘贴过大时不发送，提示“粘贴内容超过容量”。程序显示图片或通过 OSC 52 写剪贴板在网页中不起作用。

手机快捷键常驻一行是 SHIFT、CTRL、ALT 和 ←、↓、→，展开后多一行 TAB、/、@、PGUP、↑、PGDN、ESC；“收起快捷键”连同 ↑ 一起收起。SHIFT、CTRL、ALT 点一次对下一个按键生效，再点取消。网页中的 Ctrl-b 直接发给程序，不是 tmux 前缀。

### 搜索与显示

“搜索终端”在当前画面已加载的内容（含历史）中查找，不区分大小写：Enter 下一个，Shift-Enter 上一个，Esc 关闭。会话菜单的“增大字号”“减小字号”调整当前画面，并作为这个浏览器之后打开终端的字号。

“终端设置”中的“新会话滚屏行数”决定会话保留多少行历史（范围见[限额](reference.md#限额)），只对之后新建的会话生效。

一个会话只有一组行列，由最近输入或调整窗口的客户端决定，其他客户端随之重排；手机打开输入法不改变尺寸。

### 连接与恢复

打开会话时显示“正在连接”，恢复画面和历史后才能输入。可能出现的提示：

| 提示                     | 处理                                           |
| ------------------------ | ---------------------------------------------- |
| “连接已断开”             | 点“重新连接”                                   |
| “终端记录器不可用。”     | 程序仍在运行，点“恢复终端”                     |
| 容量不足、超时或资源正忙 | 点“重新连接”，或“减少历史后重试”只恢复当前画面 |
| “已减少较早历史”         | 本次省略了较早的滚屏，设备上的历史不变         |
| “历史存在缺口”           | 记录器曾故障，期间的部分输出缺失               |
| “已结束”                 | 会话已结束，画面只读，括号中是退出码           |

“恢复终端”重建记录后重新附着到同一个程序，不重启程序。连接正常但画面错乱时，用会话菜单的“重绘程序”：它临时改变一次尺寸让程序重绘，其他客户端的画面和选区也可能变化，所以要先确认。仍不正常时“关闭显示”后重新打开。机制见[恢复动作](../design/terminal.md#恢复动作)。

会话菜单的“结束会话”确认一次后，结束会话及其中的全部程序。

### 本机接续

网页会话菜单的“本机接续命令”给出附着到该会话的命令，在设备上以项目用户、在真实终端中执行，不需要 sudo。例如：

```sh
/usr/local/bin/kiteline-agent attach SESSION_ID --run-dir '/home/PROJECT_USER/.local/share/kiteline-agent/run'
```

附着后，Ctrl-b d 断开附着（会话继续），Ctrl-b Ctrl-b 发送 Ctrl-b，Ctrl-b [ 用 tmux 复制模式查看历史。agent 运行时也可以在本机管理会话：

```sh
kiteline-agent workspace list
kiteline-agent terminal new --workspace WORKSPACE_ID
kiteline-agent terminal list --workspace WORKSPACE_ID
kiteline-agent attach SESSION_ID
kiteline-agent terminal end SESSION_ID
```

`workspace list` 给出工作区 ID，`terminal new` 创建会话后立即附着。各命令的输出和选项见 [kiteline-agent 命令](reference.md#kiteline-agent-命令)。

Windows 上在 PowerShell 7 中把 `kiteline-agent` 换成 `& "$env:ProgramData\kiteline-agent\kiteline-agent.ps1"`（两种写法见 [kiteline-agent 命令](reference.md#kiteline-agent-命令)）。本机命令和 agent 必须解析到同一个运行目录（见 [agent 环境变量](reference.md#agent-环境变量)）；只在服务配置中设置了 `KITELINE_AGENT_RUN_DIR` 时，本机命令也要设置同样的变量，`attach` 也可以用 `--run-dir`（网页复制的命令已包含）。容器见[在容器中运行](devices.md#在容器中运行)。

## 文件

文件工具浏览和编辑当前工作区的文件，路径相对于工作区目录显示。

### 浏览

桌面左侧是目录树，手机逐层进入。目录很大时点“加载更多”继续读取。行尾菜单有“详情”和其他操作。文件名不是合法 UTF-8 的项显示“名称编码不支持”，FIFO、socket 和设备节点显示为“特殊文件”，这些项请在终端处理。

文件被其他程序改动后列表自动刷新，页面可见时也定时刷新。设备无法监听目录时顶部提示“自动监听受限，定时刷新仍可用”。“更多文件操作”中有“刷新”。

### 打开与编辑

PNG、JPEG、GIF、WebP 图片按内容识别并预览，其他文件按 UTF-8 文本打开。包含 NUL 字节、不是合法 UTF-8 或超过编辑容量（见[限额](reference.md#限额)）的文件无法编辑，可以“下载文件”。

编辑器保留原有的 BOM、换行符和末尾换行；混用换行时提示“混合换行；保存采用 {{format}}”（LF 或 CRLF）。用“保存文件”或 Ctrl-S（macOS 为 Cmd-S）保存，工具栏还有“另存为”“复制文本”和“核对磁盘内容”。一次修改会让内容超过编辑容量时整体不生效，提示“内容超过单文件编辑容量”。

复制成功后，当前文件或“打开的文件”中的对应条目显示“已复制”；这不表示内容已保存。

保存时 agent 先写入同目录的临时文件 `.kiteline-<随机 ID>.tmp` 再替换原文件，目录里会短暂出现这个文件；agent 异常退出留下的临时文件在下次启动时清理。保存符号链接时写入它指向的文件，保留原文件的普通权限位。

### 草稿

未保存的修改（草稿）只存在于当前页面：

- 切换文件、工具、工作区或设备时保留。未保存的标签带圆点；更多菜单的“打开的文件”列出所有设备上打开的文件，可以复制或关闭。
- 关闭有修改的文件时询问“保存修改？”，可选“放弃修改”或“保存并关闭”。
- 刷新或关闭页面时浏览器会提示，确认离开后草稿丢失。
- 设备离线、设备或工作区被删除时，内容仍可查看和复制，但不能保存到原位置。

### 保存冲突

文件自打开或上次保存后被改过时，保存不执行，显示“当前状态已变化，请刷新核对后继续。”点“核对磁盘内容”打开“磁盘内容已变化”，显示磁盘上的当前文本：“加载磁盘版”放弃你的修改，“覆盖此版本”用你的内容覆盖它，“取消”暂不处理。

文件打开期间被修改时，编辑区上方提示“磁盘内容已变化”，不会自动重新加载。保存结果不确定（例如保存中断线）时提示“结果未确认”，点“核对磁盘内容”：一致时提示“磁盘内容与上次发送内容一致”，否则显示磁盘版本供选择。机制见[保存](../design/files.md#保存)。

### 图片预览

图片可以“适合屏幕”“实际尺寸”“放大图片”“缩小图片”“重新读取图片”和“下载文件”。超过预览大小或像素数的图片只能下载。

### 搜索

点“搜索文件或内容”，选择“正文”或“文件名”后输入，点结果打开文件，正文结果定位到行。规则：

- 按字面文本匹配，区分大小写。
- “文件名”在文件的相对路径（含目录部分）中查找包含查询文本的文件，结果只有文件。
- 包含隐藏文件，不搜索 `.git`，不进入任何符号链接（指向文件或目录的都不进入）。
- `.gitignore` 只在 Git 仓库内生效，`.ignore` 和 `.rgignore` 始终生效；勾选“包含已忽略项”可搜索被这些规则排除的文件。
- 结果数量和时间有上限（见[限额](reference.md#限额)），达到时显示“结果不完整”；路径不是合法 UTF-8 的结果不显示，也标为不完整。

### 新建与重命名

“新建文件”和“更多文件操作”中的“新建目录”在当前目录创建，新文件直接打开。名称已存在时新建和“重命名”都失败，不覆盖。重命名或移动后，打开的标签跟随到新路径。工作区根目录和正在保存的文件不能重命名、移动或删除。

### 上传与下载

上传：在“更多文件操作”中点“上传文件”，选择一个或多个文件（不能选目录），可以修改每个文件的目标路径，点“上传”逐个发送。数据发完显示“等待设备完成”，完成后显示“已上传”。上传中可以“收起”对话框，之后从上传状态重新打开，或“取消上传”。

下载：文件菜单的“下载”、选择模式的“下载所选文件”或编辑区的“下载文件”交给浏览器的下载管理器；失败时页面顶部按“下载 {{path}}：{{error}}”显示。目录不能下载。大小上限见[限额](reference.md#限额)。

### 整理文件

单项用文件菜单的“复制”“移动”“删除”；多项先在“更多文件操作”中点“选择文件”，勾选后操作。复制和移动时填写“目标目录”，也可以修改每项的目标路径；在同一目录复制时预先填好不冲突的名称。执行期间对话框不能关闭，可以“取消操作”。

- 复制目录会递归复制，符号链接复制为链接本身，硬链接复制为独立文件。
- 同一文件系统内移动是改名，跨文件系统移动先复制再删除源。
- 目标已存在时该项失败，不覆盖文件，不合并目录，见[同名处理](#同名处理)。

删除确认一次后执行，是永久删除，没有回收站。目录递归删除，包括挂载在其中的其他文件系统里的数据，此时提示“永久删除所选内容及目录内挂载的共用数据？挂载点可能保留。”删除符号链接只删链接本身。FIFO、socket 和设备节点不能复制、移动或删除，包含它们的目录只能部分删除。

### 同名处理

上传、复制或移动的目标已存在时，点该项的“同名处理”：

- “保留两份”：使用“保留两份的路径”，默认是建议名，例如 `config (2).json`、`src (2)`、`.env (2)`。如果执行时建议名已被占用，该项仍会失败。
- “替换”：覆盖这个文件，该项显示“已确认替换目标目录项”。目录不能替换；确认后目标又被改动时，替换不执行。目标是符号链接时提示“替换将移除符号链接，原目标文件不变。”

每项旁的“跳过”表示不处理这一项。

### 操作结果与取消

每项结果为“已完成”“未完成”（未执行或确认失败，磁盘没有变化）、“部分完成”（例如目录中的部分文件已处理）或“结果未确认”（执行中失去联系，先查看磁盘再决定）。取消只停止尚未开始的部分，已完成的部分保留。未完成的项可以修改后“重试未完成项”。

### 符号链接

文件工具跟随项目用户能访问的符号链接，可以经链接浏览工作区外的目录，指向目录的链接菜单中有“进入链接目录”。打开和保存作用于链接指向的文件，重命名、移动、删除和替换只作用于链接本身。

目录上传、打包下载和跨工作区复制等不在文件工具中提供，见[范围外](../design/files.md#范围外)。

## Git

Git 工具使用设备上的 Git 和项目用户的 Git 配置，hooks、签名和凭据按设备配置生效。设备需要 Git 2.23.0 及以上版本，见[支持的系统与准备](devices.md#支持的系统与准备)。

### 仓库发现与切换

Git 工具扫描工作区目录及其所有子目录，列出找到的仓库，包括已初始化的子模块和位于工作区内的 linked worktree（标为 `worktree`）。工作区之外的仓库不会被使用：工作区如果只是某个仓库的子目录，会显示“没有发现 Git 仓库”，请把仓库根目录添加为工作区。

有多个仓库时自动选中第一个，用左上角的仓库菜单按路径切换。“重新发现仓库”重新扫描；显示“仓库扫描未完成”时点“继续扫描”。裸仓库不支持。

### 状态与 diff

“变化”视图顶部显示当前分支、上游以及领先（↑）和落后（↓）的提交数。列表分为“冲突”“暂存的更改”“更改”三组，未跟踪文件在“更改”中。点一项查看单栏 diff；diff 太大时显示“Diff 超过显示行数”或“Diff 读取已截断”及部分原始 patch。变化很多时用“Git 上一页”“Git 下一页”翻页，组标题的数量是整个仓库的。路径不是合法 UTF-8 的项不能操作。列表自动刷新，“刷新 Git”立即刷新。

### 暂存与提交

每行的加号暂存，减号取消暂存；勾选多行后用组标题上的按钮批量操作。

- 暂存的是磁盘上的文件。所选文件有未保存的草稿时先询问“所选文件有未保存修改。暂存设备上的磁盘版本？”
- 操作会连带改变未选中的路径时不执行，并列出这些路径和需要先做的操作。
- 已暂存的重命名，减号同时取消新旧两个路径；行菜单的“只取消暂存新路径”只取消新路径。

在“提交消息”中输入后点“提交”（手机上先点“提交”打开输入框）。提交包含暂存区的全部内容，不限于当前页或勾选的行。消息为空、有未解决的冲突或没有暂存的更改时不能提交。

### 丢弃更改

行菜单有“丢弃未暂存更改”（恢复为暂存区中的版本）和“丢弃全部更改”（恢复为 HEAD 中的版本）。对话框先逐项列出将“恢复”还是“删除”，确认后点“丢弃”。列为“删除”的文件（例如未跟踪文件）被永久删除。列出之后文件又变化时不执行，需要重新审查。

### 分支与历史

“分支”视图列出本地分支，被其他工作树检出的分支显示其路径，不能切换或删除。切换不强制覆盖本地修改；删除执行 `git branch -d`，未合并的分支会被拒绝；Git 拒绝时显示[结果未确认](#结果未确认)。“创建分支”时可勾选“创建后切换”，历史中也可以“从此提交创建分支”。

“历史”视图按页列出提交。点提交查看改动的文件，再点文件查看与父提交的 diff，合并提交可以选择父提交。

### 同步与认证

仓库标题行右侧有 Fetch（可选远端）、Pull 和 Push 按钮，提示中显示操作目标。Pull 执行 `git pull`，合并时使用默认提交消息，配置为交互式 rebase 的 pull 会失败。Push 执行 `git push`，没有强制推送。

认证无法交互，Git 不会弹出用户名或密码输入：SSH 密钥、ssh-agent 或凭据助手必须在 agent 的环境中无需输入即可使用。认证失败时，点反馈中的“终端”，在同一工作区的终端里运行相同的 Git 命令完成配置（例如让凭据助手保存凭据），再回来重试。agent 作为服务运行时见[后台运行](devices.md#后台运行)，机制见[同步与认证](../design/git.md#同步与认证)。

### 冲突与继续

仓库处于 merge、rebase、cherry-pick、revert 或 am 中时（包括在终端中开始的），顶部显示操作名称和原因，并提供“继续”“中止”和“在终端处理”：

1. 在文件工具或终端中解决冲突并保存。
2. 在 Git 中点冲突行的加号，标记已解决。
3. 没有冲突后点“继续”，使用默认的提交消息。

“中止”确认后让 Git 恢复操作前的状态，未提交的内容可能受影响。网页只能继续由普通 pick 步骤组成的 rebase；含 edit、reword、squash、fixup、exec 等步骤的 rebase 和无法识别的操作，请在终端中完成后回到网页刷新。见[冲突与进行中的操作](../design/git.md#冲突与进行中的操作)。

### 结果未确认

同一仓库一次执行一个 Git 写操作，其余排队，执行中可以“取消操作”。以下情况下工作台无法确定仓库的状态，显示“结果未确认。请刷新核查后再决定是否重试。”：

- Git 命令以失败状态退出，例如 push 被拒绝、hook 拒绝提交、存在 `index.lock`；
- 执行中失去联系；
- 操作被取消；
- 超过写操作时限（见[限额](reference.md#限额)）。

处理：展开“Git 输出”查看 Git 的原始输出，点“刷新 Git”确认分支、提交和变化，确认没有生效后再手动重试。工作台不会自动重试。

多步操作只完成一部分时显示“操作部分完成。”机制见[结果语义](../design/protocol.md#结果语义)。Stash、按行暂存等需要在终端中完成，见[范围外](../design/git.md#范围外)。

## 访问开发服务

工作台可以打开设备上监听本机端口的 HTTP 服务，包括 WebSocket（含热更新）和 SSE。链接需要工作台登录，不是公开分享。关闭页面不会停止开发服务；退出登录、登录到期或删除设备会断开已打开的连接。

### 打开端口

选定设备后点顶栏的“访问端口”：输入“端口”或点“监听端口”中的候选，选择“普通路径”或“保留路径”，点“打开”或“复制链接”。候选是一次快照，“刷新监听端口”重新读取，可能包含非 HTTP 服务；未列出的端口也可以手工输入。

服务必须在 agent 所在的机器（或容器）中监听 `127.0.0.1`、`::1`、`0.0.0.0` 或 `::`。容器见[在容器中运行](devices.md#在容器中运行)，候选规则见[端口建议](../design/http-access.md#端口建议)。

终端输出中主机为 `localhost`、`127.0.0.1`、`[::1]`、`0.0.0.0` 或 `[::]` 的 `http:` 链接会转换为该设备端口的地址：桌面上点击打开，手机上长按选中完整链接后点“访问设备端口”。其他链接按原地址打开。

### 两种路径模式

| 模式       | 地址                         | 开发服务收到的路径 |
| ---------- | ---------------------------- | ------------------ |
| “普通路径” | `/proxy/DEVICE_ID/PORT/…`    | 去掉前缀           |
| “保留路径” | `/absproxy/DEVICE_ID/PORT/…` | 包含完整前缀       |

“普通路径”适合只使用相对地址的页面。页面用 `/` 开头的路径引用资源时，请求会落到工作台根路径，表现为空白页或 MIME 类型错误；这类项目改用“保留路径”，并把项目的 base 设为 `/absproxy/DEVICE_ID/PORT/`。

开发服务收到的 `Host` 是你访问工作台的地址（如 `kiteline.example.com:8443`），工作台的登录 Cookie 不会转给它。完整规则见[地址与路径模式](../design/http-access.md#地址与路径模式)。设备 ID 可以从设备页地址 `/devices/DEVICE_ID` 取得，或选“保留路径”后“复制链接”。

### 配置 Vite

Vite 项目使用“保留路径”，在 `vite.config.js` 中设置：

```js
export default {
  base: "/absproxy/DEVICE_ID/3000/",
  server: {
    port: 3000,
    strictPort: true,
    allowedHosts: ["kiteline.example.com"],
    proxy: {
      "/absproxy/DEVICE_ID/3000/api": {
        target: "http://127.0.0.1:8000",
        rewrite: (path) => path.replace("/absproxy/DEVICE_ID/3000", ""),
      },
    },
  },
};
```

- `DEVICE_ID` 换成设备 ID，`3000` 换成开发服务端口。
- `allowedHosts` 列出访问工作台用的每个域名，不带端口；用 IP 或 `localhost` 访问时不需要。缺少时 Vite 返回 403 和 `Blocked request`。
- `server.proxy` 的键必须带 base 前缀，否则请求得到的是 `index.html`。上例中后端收到去掉前缀的 `/api/…`。
- Vite 处理的 HTML 资源自动加上 base，热更新默认经同一地址连接，不需要另外配置。

应用代码自己拼接的地址从 base 构造，路由器的 base 也用同一前缀：

```js
const base = new URL(import.meta.env.BASE_URL, location.origin);
fetch(new URL("api/status", base));
const socketUrl = new URL("socket", base);
socketUrl.protocol = location.protocol === "https:" ? "wss:" : "ws:";
const socket = new WebSocket(socketUrl);
```

### 常见错误

- 跳转到登录页：这个浏览器未登录或登录已到期，登录后自动回到原地址。
- 502：端口上没有服务、服务只监听其他地址或不是 HTTP 服务。
- 503：设备离线。426：agent 与 server 版本不一致，见[升级 agent](devices.md#升级-agent)。404：设备 ID 不存在。
- 504、429：连接超时或设备连接数已满，稍后重试。
- 空白页、MIME 类型错误：改用“保留路径”并配置 base。

这些错误页由工作台生成，是英文的；开发服务自己返回的错误原样显示。完整状态码见[错误响应](../design/http-access.md#错误响应)。

### 安全提示

开发页面与工作台同源（协议、域名、端口相同）。页面中的脚本可以像你一样调用工作台接口，包括在任何设备上执行命令、改写文件；所有项目和端口的页面共用 `Path=/` 的 Cookie、localStorage 和 Service Worker，可能互相覆盖，页面返回的 `Clear-Site-Data` 能清掉工作台登录。只打开你信任的项目，不要经这里访问来源不明的服务。机制见[安全边界](../design/http-access.md#安全边界)。
