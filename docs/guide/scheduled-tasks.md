# 定时任务

定时任务保存在设备上，由该设备的 agent 按计划在后台执行非交互命令，例如定期运行脚本或 AI CLI。本文面向拥有者，说明如何在网页和设备本机的 `kiteline-agent schedule` 中管理同一份任务；机制见[定时任务契约](../design/scheduled-tasks.md)。

## 创建与编辑

从顶栏、主页或设备详情打开“定时任务”。页面按设备列出任务，顶部的设备选择框可以只显示一台设备，或选“全部设备”。设备离线时，列表显示 server 保存的最近摘要（“最后读取于 …，当前状态不可用。”），这时不能编辑或运行任务。

点“新建任务”打开表单：

| 字段       | 说明                                                                      |
| ---------- | ------------------------------------------------------------------------- |
| “设备”     | 任务所属的设备，保存后不能更改                                            |
| “名称”     | 必填                                                                      |
| “计划”     | “单次”“每小时”“每天”“每周”或“Cron（五字段）”，规则见[计划规则](#计划规则) |
| “命令”     | 必填，交给 Shell 执行的命令文本                                           |
| “工作目录” | 留空时为“设备 HOME”；“选择工作区目录”可填入某个工作区的路径               |
| “调度时区” | 留空时为“设备时区”                                                        |

“工作目录”和“调度时区”在折叠的“工作目录与调度时区”中。常用周期按调度时区换算成 Cron 表达式：

| 周期     | 含义                       | 表达式      |
| -------- | -------------------------- | ----------- |
| “每小时” | 每小时第 0 分              | `0 * * * *` |
| “每天”   | 每天的指定“时间”           | `M H * * *` |
| “每周”   | 每周指定“星期”的指定“时间” | `M H * * D` |

表单下方的“下次执行 · 浏览器本地”显示设备算出的接下来 3 次执行时间，按浏览器所在时区显示并标出偏移。预览和保存使用同一套规则，预览报错时保存也会失败。

工作目录必须是设备上已存在的目录，在新建或修改它时检查。目录之后被删除或移走，该次运行失败，原因显示“命令无法启动”。

### 编辑与删除

在任务详情点“编辑任务”。保存只提交改过的字段。正在执行的运行继续使用开始时的命令和工作目录，修改从下一次运行起生效。

打开表单后，任务若被其他浏览器或命令行修改过，保存会失败并提示“任务已被其他入口修改。请先读取当前定义，再保存你的编辑。”你的输入会保留。点“读取当前定义”查看“当前定义”，核对后再次保存。连接中断导致保存结果不明时，表单显示“任务 ID”和“查询结果”按钮，用它确认任务是否已经保存，不要重复提交。

点“删除”并确认后，任务定义和它保留的运行记录一起删除，命令写出的文件保留。任务有运行未结束时不能删除，先停止该运行。

## 计划规则

### Cron 表达式

使用五个数字字段：分、时、日、月、星期。每个字段可以是 `*`、数字、列表（`1,15`）、范围（`1-5`）或步长（`*/10`）。星期用 0 至 6 表示，0 是星期日。英文名称（如 `MON`）、秒字段和 `@daily` 之类的写法不被接受。表达式长度有上限（见[限额](reference.md#限额)），并且必须至少有一次未来的执行时间。

同时限定“日”和“星期”时，两者满足其一即执行。例如 `0 9 13 * 5` 在每月 13 日和每个星期五的 09:00 执行。

### 单次计划

网页的“日期与时间（浏览器本地）”按浏览器所在时区输入。命令行的 `--at` 使用带秒的 ISO 8601 时间，并带 `Z` 或 `+08:00` 这样的偏移，例如 `2027-01-05T09:00:00+08:00`；`2027-01-05T09:00+08:00` 会被拒绝。时间必须在未来。

单次计划最多执行一次，状态依次显示为“待执行”“计划已消耗”或“已错过”。计划时刻因“上次运行仍未结束”或“设备运行数量已达上限”被跳过时，单次计划同样变为“计划已消耗”，命令没有执行，之后也不会再执行；需要时修改计划时间重新安排。“立即运行”不消耗单次计划。修改计划时间会生成新的单次计划，状态回到“待执行”。

### 调度时区

Cron 表达式按任务的调度时区解释，时区写 IANA 名称，例如 `Asia/Shanghai`；`+08:00` 这样的固定偏移会被拒绝。不指定时使用保存时设备的时区，并随任务保存，之后不随浏览器或设备时区变化。调度时区只决定何时执行，命令运行时的 `TZ` 环境变量仍来自 agent。

夏令时切换时，不存在的本地时间被跳过，重复出现的本地时间只执行一次。

### 错过的执行

计划时刻到来时 agent 没有运行或任务处于暂停，这次执行被跳过，之后也不补跑。agent 启动或任务恢复后，从当前时间计算下一次执行。

agent 在运行但计时器晚于计划时刻且超过迟到容差（见[限额](reference.md#限额)，例如系统刚从休眠中恢复），这次执行记为“已跳过”，原因是“已错过计划时间”。单次计划的时间在 agent 停止或任务暂停期间过去时，这次计划不会执行；agent 下次启动或任务被恢复、修改时，状态变为“已错过”，并留下一条“已跳过”记录。

## 执行环境

命令由 agent 配置的 Shell 以非交互方式执行（Linux、macOS 为 `SHELL -c COMMAND`，Windows 为 PowerShell 7 的 `-Command`），Shell 的默认值和完整参数见 [shell](reference.md#shell)。

- Shell 既不是登录 Shell，也不是交互 Shell。命令依赖的设置若来自 `~/.bashrc`、`~/.profile` 或 PowerShell profile，请把它们写进命令，或放进 agent 的启动环境。
- 标准输入已关闭，也没有终端（PTY）。需要终端或等待人工确认的程序会失败或立即读到输入结束，AI CLI 需要使用它的非交互方式运行。
- 命令以 agent 的操作系统用户运行，继承 agent 进程的环境，包括 `HOME`、`PATH`、代理变量、SSH agent 和 Git 凭据。它不继承执行 `kiteline-agent schedule` 的那个 Shell 的环境和当前目录。agent 作为后台服务运行时，环境由服务配置提供，见[后台运行](devices.md#后台运行)。
- 默认工作目录是项目用户的 HOME（Windows 上是用户配置文件目录）。
- 没有默认的运行时长上限，命令一直运行到退出或被停止。输出超过限额也不会结束命令。
- 命令在独立的进程组（Linux、macOS）或 Job（Windows）中运行，停止时作用于其中所有进程。命令应在前台完成工作；在 Linux 和 macOS 上，自行脱离进程组的后台进程不受停止操作管理。
- 定时任务不进入 tmux，不能附着，结果通过运行记录查看。

退出码为 0 时运行结果为“成功”；非 0 时为“失败”，原因“命令未成功退出”；工作目录或 Shell 不可用导致无法启动时为“失败”，原因“命令无法启动”。

## 运行与停止

- **立即运行。** 在任务详情点“立即运行”，设备接受后打开这次运行的详情。请求成功只表示运行已被接受；关闭浏览器或命令行不会停止它。
- **并发。** 同一任务同时只有一次运行，每台设备同时运行的数量有上限（见[限额](reference.md#限额)）。条件不满足时，“立即运行”报“资源正忙。”；定时执行不排队，直接记为“已跳过”，原因是“上次运行仍未结束”或“设备运行数量已达上限”。
- **暂停与恢复。** “暂停计划”停止之后的定时执行，正在执行的运行不受影响，暂停期间仍可“立即运行”。“恢复计划”从当前时间重新计算下一次执行。
- **停止。** 在运行详情点“停止运行”并确认“停止本次运行？命令已经完成的改动仍会保留。”Linux 和 macOS 向整个进程组发送 `SIGTERM`，等待停止宽限（见[限额](reference.md#限额)）后仍未结束则发送 `SIGKILL`；Windows 立即结束整个 Job。运行依次显示“停止中”“已停止”，原因是“已请求停止”。
- **agent 正常停止。** 用 Ctrl-C、服务管理器或升级前停止 agent 时，正在执行的运行按同样方式停止，记为“已停止”，原因是“Agent 已停止”。任务定义和记录保留，agent 再次启动后继续按计划执行。
- **不自动重试。** 失败或跳过的执行不会重试，下一次计划照常执行。

“立即运行”的结果不明时，页面显示“运行 ID”和“查询结果”按钮。先用它确认运行是否已经开始，再决定是否重新运行。结果语义见[结果语义](../design/protocol.md#结果语义)。

## 运行记录与输出

任务详情的“最近执行”按时间倒序列出运行记录。运行详情显示：

- 状态、触发方式（“手动”或“定时”）、原因、“退出码”或“信号”；
- “接纳时间”“开始时间”“结束时间”；
- “命令与执行环境”：这次运行使用的命令、工作目录和 PID；
- stdout 和 stderr，分开显示，两者之间没有统一的时间顺序。

运行详情可见时，网页每 2 秒读取新输出，回看旧输出时不会被拉到底部。

输出和记录有保留上限，数值见[限额](reference.md#限额)：

- 每次运行的 stdout 和 stderr 合计有上限。超出部分不保存，命令继续运行，详情提示“输出不完整或已超过保留限额。”
- 每个任务只保留最近 `taskHistoryRuns` 条已结束的记录，“已跳过”的记录也计入。
- 设备上的输出总量有上限。开始新运行时，如果剩余空间不足一次运行的输出上限，agent 从最早的已结束记录起删除带输出的记录，直到空间足够；删除全部可删记录仍不够时，不删除任何记录，新运行的输出会更早被截断。正在执行和待核查的运行不会被删除。

记录保存在 agent 数据目录的 `tasks/` 中（见[文件位置](reference.md#文件位置)），agent 重启和升级后仍在，`uninstall --purge-state` 会删除它们。打开已被清理的记录时显示“记录不存在或已清理。再次运行前，请核查此前的执行情况。”记录不存在不能证明命令从未执行。命令自己写出的文件留在原处；位于工作区内时可以在“文件”中查看。

## agent 重启后的核查

agent 异常结束（进程被杀、崩溃、断电）时，正在执行的运行没有可信的最终结果。agent 下次启动时：

1. 把这些运行标为“未知”，原因是“上次运行结果未确认”；
2. 暂停对应任务，任务显示“待核查”和提示“请先核查上次运行的进程。确认核查后任务保持暂停。”；
3. 在核查完成前拒绝该任务的定时执行和“立即运行”，这次运行继续占用设备的运行名额。

核查步骤：

1. 打开提示中的运行 ID，在“命令与执行环境”中查看命令和 PID。Linux 和 macOS 上命令在独立进程组中运行，agent 结束后它可能仍在运行；按 PID 和命令确认它是否还在，需要时自行结束它。Windows 上命令所在的 Job 随 agent 结束，进程一并结束。
2. 检查命令已经产生的影响，例如写了一半的文件。
3. 点“确认核查”，确认“我已核查运行 …，确认旧程序已结束。是否继续？”。任务仍保持暂停，记录仍为“未知”。
4. 需要继续按计划执行时，点“恢复计划”。

待核查的任务也可以直接删除，删除确认中包含同样的核查确认。

agent 启动时无法读取 `tasks/` 中的文件时，该设备的任务功能显示“此设备的任务存储不可用。”，agent 日志以 `Scheduled task storage:` 开头写出出错的文件。终端、文件和 Git 不受影响。修复或移走出错的文件后重启 agent。agent 不会自动修复或删除这些文件。

## 命令行

`kiteline-agent schedule` 在设备本机管理同一份任务。它通过本机 socket 或命名管道连接正在运行的 agent，因此必须由运行 agent 的同一操作系统用户执行，并解析到相同的运行目录。它不会启动 agent；agent 未运行时，除 `--help` 外的命令都会报错退出。`--help` 随时可用，内容包括完整的规则和示例。

Windows 上在 PowerShell 7 中写成 `& "$env:ProgramData\kiteline-agent\kiteline-agent.ps1" schedule …`（两种写法见 [kiteline-agent 命令](reference.md#kiteline-agent-命令)）。

| 子命令                                | 作用                                                       |
| ------------------------------------- | ---------------------------------------------------------- |
| `list [--offset N]`                   | 分页列出任务                                               |
| `show TASK_ID`                        | 查看任务定义                                               |
| `create`                              | 新建任务，必填 `--name`、`--command` 和 `--cron` 或 `--at` |
| `update TASK_ID`                      | 只修改给出的字段                                           |
| `preview`                             | 按 `--cron` 或 `--at` 和 `--timezone` 计算接下来的执行时间 |
| `run TASK_ID [--run-id ID]`           | 立即运行                                                   |
| `pause TASK_ID`、`resume TASK_ID`     | 暂停或恢复计划                                             |
| `acknowledge TASK_ID --run-id RUN_ID` | 确认核查                                                   |
| `runs TASK_ID [--offset N]`           | 分页列出运行记录                                           |
| `status RUN_ID`                       | 查看一次运行的状态、退出码和信号                           |
| `output RUN_ID`                       | 读取输出                                                   |
| `stop RUN_ID`                         | 停止一次运行                                               |
| `delete TASK_ID`                      | 删除任务及其记录                                           |

```sh
kiteline-agent schedule preview --cron '0 9 * * 1-5' --timezone Asia/Shanghai --json
kiteline-agent schedule create --name 'Daily review' --cron '0 9 * * 1-5' --timezone Asia/Shanghai --cwd '/srv/My Project' --command './daily-review.sh' --json
kiteline-agent schedule run TASK_ID --json
kiteline-agent schedule status RUN_ID --json
kiteline-agent schedule output RUN_ID --stream stdout --offset 0 --json
```

### 参数与输出

- `create` 和 `update` 的字段：`--name`、`--command`、`--cron EXPR` 或 `--at ISO_DATE`（二选一）、`--cwd PATH`（已存在的绝对路径）、`--timezone IANA_ZONE`。
- `update` 默认先读取任务当前的修订号再提交；用 `--expected-revision N` 指定修订号时，任务在此之后被改过则报冲突，需要重新读取并核对后再更新。
- `output` 的 `--stream` 取 `stdout`（默认）或 `stderr`；`--offset` 是字节偏移；`--limit` 是本次读取的字节数，范围见[限额](reference.md#限额)。结果中的 `nextOffset` 是下一次读取的起点。
- `delete` 在终端中询问确认，没有终端时必须加 `--yes`；任务待核查时还要加 `--acknowledge-run RUN_ID`。
- `--json` 让标准输出只有一个 JSON 对象：成功时为 `{"outcome":"succeeded","result":…}`，失败时为 `{"outcome":…,"error":{…},"taskId":…,"runId":…}`。诊断信息写到标准错误。不加 `--json` 时打印缩进后的结果 JSON。

### ID

任务 ID 和运行 ID 由字母、数字、`_` 和 `-` 组成，长度上限见[限额](reference.md#限额)，不区分大小写地唯一。`create --task-id` 和 `run --run-id` 可以由调用方指定 ID，省略时自动生成。ID 在任务和记录的整个生命周期内不变，查询、停止和核查都用它。

### 退出码

| 退出码 | 含义                                                               |
| ------ | ------------------------------------------------------------------ |
| 0      | 管理操作成功，或运行已被接受                                       |
| 1      | 管理操作确定失败，例如资源正忙、修订冲突、对象不存在、agent 未运行 |
| 2      | 用法错误或参数无效，例如 Cron 表达式不合法、工作目录不是目录       |
| 3      | 结果未确认：请求已发出但没有收到结果                               |

`run` 或 `status` 以 0 退出不代表命令执行成功，要查看运行的状态和退出码。退出码为 3 时，按输出中的 `taskId` 或 `runId` 查询结果，不要直接重发同一操作。

### 让 AI CLI 管理任务

“定时任务”页面的“给 agent 的提示词”提供一段提示词模板，可切换“中文”或“English”，再点“复制提示词”。把它连同你的需求交给设备终端中的 AI CLI，它会先阅读 `kiteline-agent schedule --help`，再用命令行创建和管理任务。
